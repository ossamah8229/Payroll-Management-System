Generated 2026-07-11 for Phase 4 Checkpoint 2 (Finance Role + Salary Release foundation) from frontend/src/routes/salary-release-page.tsx, frontend/src/hooks/use-payroll-release.ts, and backend/src/modules/payroll-release/.

Scope, matching the implemented checkpoint exactly: release is by Project Unit only, executed exclusively by Finance (or Master User) via payroll:release — Payroll Staff never holds it. A release inserts an immutable PayrollUnitRelease row and, in the same transaction, sweeps every non-held PayrollEntry at that Unit's Site whose work lines touch it; an entry only flips to released = true once every distinct Unit it touches has its own release row — the "After release" tab above depicts exactly that split-entry case. There is no un-release action. PayrollUnitReadiness ("Ready for Release") and the Late Entry one-off release path are both deliberately deferred to a later checkpoint, not shown here.

Every field a release freezes (site, bank, account, designation) was already copied onto PayrollEntry at entry-creation/edit time and stays untouched by a later Employee change (Phase 3) — release itself only ever flips the released/releasedAt/releasedBy flags, so the snapshot Principle 9 requires was already correct before this checkpoint; verified directly in backend/tests/payroll-release.test.ts.
