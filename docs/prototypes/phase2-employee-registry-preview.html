Updated 2026-07-04 for Phase 2.5 Checkpoints 0–2: every date field (Date of birth, Date of joining) now reads DD-MM-YYYY, backed by the shared formatDate()/DateInput component (frontend/src/components/ui/date-input.tsx) — never a native <input type="date">, which can't be forced out of the browser's OS locale. The Employment section gained a second, dependent select next to "Project site": choosing a site filters the picker to that site's own Project Units and relabels itself using the site's own unitLabel ("Branch" shown here for ABL City Region Lahore; "Department" for Metro Mall Karachi) — reproducing the new reusable frontend/src/components/ui/site-unit-select.tsx. Selecting `Employee.unitId` is now required, composite-FK'd to the chosen site so a unit from a different site can never be submitted — see backend/src/modules/employees/employees.service.ts. Editing an existing employee's site/unit is a *transfer*: it writes a dedicated, append-only `EmployeeTransferHistory` row and an `employee.transferred` audit entry (not the generic `employee.updated` entry) — see docs/architecture/database-schema.md §8b. No dedicated "record a transfer" screen exists yet (reason/effective-date fields are accepted by the API but not yet surfaced in this form).
