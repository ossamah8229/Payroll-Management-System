Payroll Staff never see "Bank Sheet" in the sidebar at all — it is gated by bank-sheets:view, held only by Finance and Master User. A direct API call to any Bank Sheet route with a Payroll Staff session is also rejected server-side (403), independent of the sidebar.

Generated 2026-07-11 for Phase 4 Checkpoint 3 (Bank Sheets) from frontend/src/routes/bank-sheet-page.tsx, frontend/src/hooks/use-bank-sheet.ts, and backend/src/modules/bank-sheets/.

Scope, matching the implemented checkpoint exactly: Bank Sheets are generated exclusively from released payroll (PayrollEntry.released = true, set only by the existing per-Project-Unit release sweep, Checkpoint 2 — the release boundary itself was not reopened or redesigned) and filtered by Bank (every active Bank) or Cash — one unified feature, not a separate Cash Receiving module. CSV and Excel export reuse this project's existing ExcelJS/csv-stringify convention, no second export framework. PayrollUnitReadiness, Late Entry release, Employee Statements, Reports, Dashboard work, and any Phase 5 functionality are all explicitly out of scope and not depicted here.

Every value on a Bank Sheet row — bank, branch code, account number, account title, designation, net salary — is read exclusively from the released PayrollEntry's own frozen columns, never from Employee's live record (Employee name/CNIC are the one exception, matching every other export already in this codebase, since PayrollEntry never copied those). Verified directly in backend/tests/bank-sheets.test.ts: changing an employee's bank, account number, and designation after release leaves a previously generated Bank Sheet byte-for-byte unchanged.

Two real defects found and fixed via this checkpoint's own real-stack Playwright pass, not shipped: (1) the totals row was originally styled position: sticky; bottom: 0, intending to pin it to the bottom of the table's horizontal-scroll container — but that container only scrolls horizontally, so the row had no bounded vertical scrolling ancestor to stick to and instead detached and floated at the page's own viewport edge. Fixed to a plain, non-sticky footer row (reflected in this prototype's own CSS). (2) A genuine, pre-existing Employee Registry bug, unrelated to Bank Sheets itself: the "New Employee" modal (employees-page.tsx's EmployeeFormModal) stays mounted between opens (only its "Edit" sibling instance remounts fresh), so its form state — bank, account number, designation, gross pay, every field — silently carried over from one employee creation to the next unless manually cleared. Caught because Bank Sheet verification depends on creating two employees with different banks back-to-back; fixed with a reset-on-open effect.
