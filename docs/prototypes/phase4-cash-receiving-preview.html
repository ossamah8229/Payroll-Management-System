Payroll Staff never see "Cash Receiving" (or "Bank Sheet") in the sidebar at all — both are gated by the same bank-sheets:view permission, reused rather than a new one (approved architecture decision), held only by Finance and Master User. A direct API call to any Cash Receiving route with a Payroll Staff session is also rejected server-side (403), independent of the sidebar.

Generated 2026-07-11 for Phase 4 Checkpoint 4 (Cash Receiving Sheets) from frontend/src/routes/cash-receiving-page.tsx, frontend/src/hooks/use-cash-receiving.ts, and backend/src/modules/cash-receiving/.

Scope, matching the implemented checkpoint exactly: a dedicated module, separate from Bank Sheets (approved architecture decision) — not a tab or filter state inside it, even though both share the same released/non-held query boundary. Cash employees are identified by the exact rule Bank Sheets already ships and tests (PayrollEntry.bankId IS NULL) — accountNumber plays no role, unchanged. No new permission was introduced: bank-sheets:view is reused for both view and export, so Finance and Master User see both documents and Payroll Staff sees neither. CSV and Excel export reuse this project's existing ExcelJS/csv-stringify convention; no PDF library was added. PayrollUnitReadiness, Late Entry release, Employee Statements, Advances, Reports, Dashboard work, and any Phase 5 functionality are all explicitly out of scope and not depicted here.

Simplified document layout, by explicit approved decision — this does not reproduce the original historical prototype's full attendance/OT/allowance/deduction breakdown. Columns are exactly: Serial No., Employee Code, Employee Name, CNIC, Designation, Site, Net Salary, Signature / Thumb Impression, Remarks. The document header (Company, Payroll Cycle, Generation Date, Generated By) and footer (Total Employees, Total Cash Amount) make it suitable to print and physically sign, without a PDF pipeline — Puppeteer/PDF generation does not exist anywhere in this codebase yet and was not added for this checkpoint.

Every value on a Cash Receiving Sheet row — designation, net salary, remarks — is read exclusively from the released PayrollEntry's own frozen columns, never from Employee's live record (Employee name/CNIC are the one exception, matching every other export already in this codebase). Verified directly in backend/tests/cash-receiving.test.ts: changing an employee's designation, and separately giving a Cash employee a bank account, after release leaves a previously generated Cash Receiving Sheet byte-for-byte unchanged.

The Signature / Thumb Impression column keeps a reserved minimum width (160px) even though it is always blank — its entire purpose is providing physical space for a real signature or thumbprint once printed, so it must never collapse the way an ordinarily-empty cell would.
